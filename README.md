# BuildHouse — Telegram Mini App (aiogram + FastAPI + SQLite)

Дом, который приносит доход, кликер «Стройка», игра «Мины» со ставками, кейсы с машинами, магазин за звёзды,
рейтинг игроков и админ-панель.

## Структура проекта
| Файл | Назначение |
|---|---|
| `main.py` | Точка входа: запуск, маршруты `/health`, раздача интерфейса |
| `config.py` | Настройки из переменных окружения |
| `db.py` | SQLite: подключение, схема, миграции (режим WAL) |
| `auth.py` | Проверка подписи Telegram (initData), блокировки, защита админ-маршрутов |
| `botapp.py` | Telegram-бот (`/start`, кнопка «Открыть») — работает в фоне |
| `buildhouse.py` | Дом: доход, прокачка, тапы, ежедневный бонус, аватар, ник |
| `games.py` | Мины, кейсы, гараж, магазин, рейтинг *(заменяет прежний `bh2.py`)* |
| `catalog.py` | Каталог машин и кейсов |
| `admin.py` | API админ-панели |
| `index.html`, `style.css` | Интерфейс |
| `app.js` | Клиент игры |
| `admin.js` | Клиент админ-панели (грузится только администратору) |

## Переменные окружения (Render → Environment)
| Переменная | Обязательно | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather |
| `WEBAPP_URL` | да | Ссылка на Mini App, `https://…` (адрес Render или GitHub Pages) |
| `ADMIN_ID` | нет | Telegram ID администратора (по умолчанию `1181838335`) |
| `DB_PATH` | нет | Путь к базе. Для постоянного хранения: `/var/data/database.db` |

## Запуск на Render
1. Загрузите все файлы в корень репозитория. **Удалите старый `bh2.py`** — его заменил `games.py`.
2. Build Command: `pip install -r requirements.txt`
3. Start Command: `uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1`  (**workers 1 обязательно** — иначе несколько копий бота конфликтуют).
4. Укажите `BOT_TOKEN` и `WEBAPP_URL`.
5. Проверьте `https://<имя>.onrender.com/health` → `{"status":"ok", …}`.
6. Отправьте боту `/start` и нажмите «🚀 Открыть».

Адрес сервера для клиента задан в `index.html` в теге `<meta name="api-base" content="…">`.
Если страница лежит на GitHub Pages — укажите там адрес Render, а в `WEBAPP_URL` — адрес GitHub Pages.

## Почему раньше долго грузилось (и что исправлено)
1. **Сервер ждал Telegram перед стартом.** `getMe` и `deleteWebhook` (до 60 с каждый) выполнялись до приёма запросов. Теперь бот стартует в фоне, сайт отвечает сразу.
2. **Клиент ждал бесконечно.** У `fetch` не было таймаута. Теперь: «будим» сервер через `/health`, показываем счётчик секунд, есть повтор и кнопка «Повторить».
3. **Блокировки SQLite.** Каждый запрос создавал таблицы и писал `last_seen`, журнал был в режиме DELETE. Теперь: схема создаётся один раз, включён WAL, `last_seen` пишется раз в 30 с, транзакции записи берут блокировку сразу.
4. **Бесплатный Render засыпает** через 15 минут без запросов, пробуждение занимает до минуты. Чтобы это убрать — заведите бесплатный монитор (UptimeRobot / cron-job.org), который открывает `https://<имя>.onrender.com/health` раз в 5–10 минут.

## Админ-панель (вкладка 🛡️ у администратора)
* **Сводка** — игроки, онлайн, деньги в игре, дома по уровням, диагностика бота/БД/диска, «Глубокая проверка БД».
* **Игроки** — поиск по ID/имени/нику, фильтры (онлайн, заблокированные, новые), сортировки, страницы по 25.
* **Карточка игрока** — доллары/звёзды/уровень (добавить или задать), подарок машины, энергия, сброс бонуса и игры, блокировка с причиной, сообщение от бота, очистка гаража, полный сброс.
* **Рассылка** — сообщение всем незаблокированным игрокам с прогрессом доставки.
* **Журнал** — кто, что и когда сделал в админке.

## Хранение данных
На Render Free диск стирается при перезапуске/деплое. Для постоянной базы подключите Persistent Disk (`/var/data`)
и задайте `DB_PATH=/var/data/database.db`. Старая база подхватывается автоматически: недостающие колонки и индексы добавляются при старте.

## Безопасность
Токен и база не попадают в репозиторий (`.gitignore`). Подпись Telegram проверяется на каждый запрос, документация API отключена,
наружу отдаются только файлы интерфейса. Админ-маршруты доступны только `ADMIN_ID`.
